## 👤 전문가 1: 서비스기획자

### 강점 확인

- 시장 규모·경쟁사·포지셔닝 분석이 체계적. 포지셔닝 갭 다이어그램 효과적.
- B2G/B2C/B2B 3채널 분리와 Phase 0~3 로드맵이 명확.
- 4P 문제 정의·KPI 테이블 구체적.

### 보완 의견

#### 1-1. 가격 가설 구체화 필요

현재 PRD §10.2 가격 가설이 "2~3만원대 가설" 수준. 아래 분석이 추가되어야 한다.

| 항목 | 현재 기술 | 필요 수준 |
|---|---|---|
| 오미 기기 가격 | "보급형 가격대" 정도 | 목표 BOM → 제조원가 → 권장소비자가격 로드맵 |
| 구독 단가 근거 | 2~3만원 가설만 | ElliQ($39/월), LifeBio($47/월) 비교 + 한국 WTP 조사 |
| B2G 단가 | 언급 없음 | 효돌 대여 단가 + 지자체 예산 상한 분석 |

#### 1-2. GTM 세부 실행 계획

현재 Phase 1~3 GTM은 채널 수준. 추가 필요:

- **Phase 1 파일럿 모집 기준:** 어르신 연령·진단·동거 여부 선정 기준
- **Phase 1 성과 측정 설계:** KPI 달성을 판단할 기준선(Baseline) 설정 방법
- **B2G 입찰 전략:** 치매안심센터 조달 절차(시범·우선구매·공개입찰 경로)
- **B2C 진입 메시지:** 자녀 세대 타깃 디지털 마케팅 채널 (인스타그램·네이버 카페·효도 선물 커머스)

#### 1-3. 추가 권고

- 제휴 전략: 보건산업진흥원 K-HOSPITAL·AI Hub 데이터 활용 협약 방향
- 지적재산 전략: 자서전 엔진·메모리그래프 알고리즘 특허 출원 로드맵

## 🔧 전문가 2: HW설계자 (오미 디바이스) — 중점 검토

> **현 PRD 평가:** 핵심 HW 스펙이 거의 없음. 아래 내용이 PRD v1.1에 포함되거나 별도 HW 아키텍처서에서 반드시 정의되어야 한다.

### 2-1. 오미 HW 스펙 정의 (현재 PRD 미포함 항목 전체)

#### 폼팩터 & 외관

| 항목 | 현재 PRD 기술 | 필요 정의 |
|---|---|---|
| 형태 | "봉제·탁상형, 비이동" | 높이·폭·무게 범위 (예: H 25~30cm, W 500~800g) |
| 재질 | 언급 없음 | 봉제 외피 소재 (항균·세탁 가능 여부), 내부 골격 소재 |
| 표정·시각 피드백 | 언급 없음 | LED 눈/귀 여부, 표정 변화 방식, 색상 |
| 낙하 내구성 | 언급 없음 | 낙하 높이 기준 (어르신 탁상 높이 약 70cm) |
| 생활방수 | 언급 없음 | IP54 이상 (음료 엎지름 대비) 권장 |

#### 음성 입출력

| 항목 | 현재 PRD 기술 | 필요 정의 |
|---|---|---|
| 마이크 어레이 | "마이크 어레이" | 마이크 수 (2~4개 권장), 형태 (MEMS 원형 배열), 빔포밍 칩 |
| Wake Word 지연 | 언급 없음 | 목표 < 500ms (로컬 처리) |
| 오디오 SNR | 언급 없음 | TV·생활소음 환경 SNR ≥ 20dB 목표 |
| 스피커 출력 | 언급 없음 | 1~3W, 어르신 청각 보조 최대 90dB@1m |
| 볼륨 조절 | 언급 없음 | 물리 버튼 또는 음성 명령, 청각 장애 어르신 대응 |

#### 컴퓨팅 & AI 추론

| 항목 | 현재 PRD 기술 | 필요 정의 |
|---|---|---|
| 메인 프로세서 | "임베디드 보드" | SBC 후보: RPi 5, Jetson Orin Nano, RK3588 등 비교 |
| NPU | 언급 없음 | 엣지 ASR 가속 위해 NPU 필수 여부 (Jetson vs 전용 NPU 칩) |
| 엣지 ASR 모델 크기 | 언급 없음 | 목표 RAM ≤ 2GB, Whisper small (244M param) 수준 |
| 메모리 | 언급 없음 | RAM 4~8GB, 저장 32~64GB (어르신 자서전 로컬 캐시) |

#### 전원 & 연결성

| 항목 | 현재 PRD 기술 | 필요 정의 |
|---|---|---|
| 전원 방식 | 언급 없음 | 상시전원(어댑터) 권장. 배터리 옵션 시 용량·충전 시간 |
| 통신 | 언급 없음 | WiFi 6 + BT 5.0 필수, LTE Cat-M1 옵션 (공공시설용) |
| USB 포트 | 언급 없음 | USB-A(사진 업로드·유물 스캔용 USB 카메라) 1개 이상 |

#### 인증 & 안전

| 항목 | 현재 PRD 기술 | 필요 정의 |
|---|---|---|
| KC 전자파 | 언급 없음 | KC 전자파 인증 필수 (국내 판매) |
| 어린이·노인 안전 | 언급 없음 | 소형 부품 없음 확인, 넘어짐 방지 받침대 |
| 발열 | 언급 없음 | 봉제 외피 내부 온도 ≤ 45°C (장기 사용 안전) |
| 노인복지용품 인증 | 언급 없음 | 노인복지법상 복지용구 인증 여부 검토 (B2G 진입 시 필요) |

### 2-3. 봉제형 vs 탁상형 트레이드오프

| 방식 | 장점 | 단점 | 권장 |
|---|---|---|---|
| 봉제형 (효돌 방식) | 친근감, 껴안기 가능, 낙하 충격 흡수 | 내부 열 방출 어려움, 세탁 불가(내부 보드) | Phase 1: 탁상형 외피 + 봉제 커버 분리 구조 |

## 💻 전문가 3: SW아키텍처 — 중점 검토

> **현 PRD 평가:** 5레이어 개요는 우수하나, 핵심 기술 결정사항(ADR)이 미정. v1.1에서 Architecture Decision Record 형태로 정의 필요.

### 3-1. 현재 아키텍처의 빈 영역

| 영역 | 현재 PRD 기술 | 필요 정의 |
|---|---|---|
| 오미 ↔ 클라우드 동기화 | 언급 없음 | 실시간 vs 배치 vs 이벤트 기반 선택 |
| 자서전 엔진 알고리즘 | "빈칸 탐지, 우선순위화" | 구체적 스코어링 로직 |
| LLM 호출 방식 | "클라우드 LLM" | Streaming vs Batch, Token 비용 추정 |
| 데이터 동의 lineage | "동의 lineage" | 기술 구현 방법 (DB 스키마 수준) |
| 엣지 폴백 프로토콜 | "엣지 폴백" | 오프라인 시 대화 범위·한계 명시 |
| MLOps 파이프라인 | "모델 평가·회귀 테스트" | 배포 주기·A/B 테스트 방법 |

### 3-2. 응답 지연 1.5초 실현 가능성 검토

```
음성 응답 파이프라인 지연 분석:

[어르신 발화 종료]
   │
   ├─ Wake Word 로컬 탐지: < 100ms (엣지)
   │
   ├─ 엣지 STT (Whisper distil 한국어): 200~400ms
   │     └ RTF(Real-Time Factor) ≤ 0.1 필요 → Jetson Orin 수준 필요
   │
   ├─ 네트워크 왕복 (LTE/WiFi → 클라우드): 50~150ms
   │
   ├─ LLM 추론 (클라우드 LLM, TTFT):
   │     └ HyperCLOVA X: ~200~500ms
   │     └ Streaming 첫 토큰(TTFT) < 200ms 확보 시 체감 개선
   │
   ├─ TTS 합성 (클라우드 or 엣지): 100~300ms
   │
   └─ 스피커 출력 버퍼: < 50ms

합계 (낙관): ~650ms ✅ 가능
합계 (평균): ~900~1,200ms ✅ 가능
합계 (비관): ~1,500~2,000ms ⚠️ 한계 초과

권고: LLM Streaming 출력 + TTS 실시간 합성(Text-to-Speech streaming) 파이프라인 필수.
      초기 토큰 재생을 시작하면서 나머지를 합성하는 방식으로 체감 지연 < 1.5초 달성 가능.
```

### 3-3. 자서전 엔진 알고리즘 설계 방향

현재 PRD가 "빈칸 탐지·우선순위화"만 언급. 구체화 필요:

```
자서전 시점×주제 매트릭스 스코어링 (제안):

각 셀(Period × Topic)에 대해:
  Coverage Score  = 0.0 (없음) ~ 1.0 (풍부)
  Recency Score   = 마지막 언급 이후 경과 시간 (최근 언급일수록 낮음)
  Emotion Score   = 감정 강도 (강한 감정 셀은 우선 탐구)
  Coherence Score = 모순·불일치 감지 시 낮아짐 (재확인 필요)

Question Priority = α × (1 - Coverage) + β × Recency + γ × Emotion
                    where α=0.5, β=0.3, γ=0.2 (초기 가설값)

→ 가장 낮은 Coverage + 오래 안 물어본 셀 우선 질문
→ 감정 고조 셀은 심화 질문 분기
```

### 3-4. 메모리그래프 규모 가설

| 항목 | 가설값 | 근거 |
|---|---|---|
| 어르신 1명 Entity 수 | ~200~500 노드 | 평균 인생 서사 인물 100명 + 장소 50개 + 이벤트 200개 |
| Edge 수 | ~500~2,000 | 관계망 |
| 벡터 임베딩 차원 | 1,536d (OpenAI) or 768d (한국어) | |
| RAG 검색 latency (pgvector) | < 50ms @ 10만 벡터 | Phase 1 규모 충분 |
| 스케일 기준 | 1,000 사용자 × 500 청크 = 500K 벡터 | Milvus 전환 검토 시점 |

### 3-6. 보안·데이터 주권 구현 방법 (상세화)

현재 PRD가 "동의 lineage"를 개념으로만 언급. 구체 구현 방향:

```sql
-- 동의 Lineage 데이터 모델 (개념)
CREATE TABLE consent_records (
  id UUID PRIMARY KEY,
  user_id UUID NOT NULL,
  data_category TEXT, -- 'autobiography', 'voice', 'health_signal'
  purpose TEXT,       -- 'family_sharing', 'research', 'service_improvement'
  consented_at TIMESTAMP,
  revoked_at TIMESTAMP,
  consented_by TEXT   -- 'self', 'guardian', 'facility'
);

-- 모든 생애사 조각에 consent_id 연결 → 동의 철회 시 cascade 삭제
```

## 🎨 전문가 4: UI/UX전문가 (접근성) — 중점 검토

> **현 PRD 평가:** "음성 우선·큰 음량·느린 발화·단순 UX"만 선언. 구체적 대화 플로우·접근성 기준·오류 UX가 전무. 이 영역은 사용자 채택률을 결정하는 핵심.

### 4-1. 어르신 접근성 원칙 (PRD v1.1 포함 필수)

#### 인지·지각 접근성 원칙

| 원칙 | 적용 방법 |
|---|---|
| 한 번에 하나의 질문 | LLM 출력에서 복수 질문 금지. 질문은 반드시 1개. |
| 짧은 문장 | TTS 출력 문장당 30자 이내 권장 |
| 느린 기본 속도 | TTS 기본 발화 속도 0.85x (일반 대비 15% 느림) |
| 반복 허용 | "다시 한번 말해주세요" → 정확히 동일 문장 재생 |
| 침묵 허용 | 발화 종료 감지 타임아웃 기본 3~5초 (일반 2초 대비 연장) |
| 호칭 유지 | 대화 전체에서 어르신이 선택한 호칭(어머님·형님 등) 100% 일관 사용 |
| 의도 추정 오류 처리 | 이해 못 한 경우 "제가 잘 못 들었어요. 다시 말씀해주시겠어요?" |

#### 시각·청각 접근성

| 항목 | 현재 PRD | 필요 정의 |
|---|---|---|
| 화면 여부 | "화면 의존 최소화" | 화면 없는 순음성 UX 기본. 화면은 보호자 앱 전용. |
| LED/표시 피드백 | 언급 없음 | 오미 귀·눈 LED: 듣는 중(파랑), 생각 중(주황 점멸), 말하는 중(초록) |
| 볼륨 조절 | "큰 음량" | 물리 볼륨 노브(+/-) 또는 "오미야 더 크게/작게" 음성 명령 |
| 청각 장애 대응 | 언급 없음 | 보청기 T-coil 연동 권고 (추후 검토) |

### 4-2. 대화 UX 플로우 (핵심 시나리오)

#### 시나리오 A: 정상 자서전 대화

```
[오미 선제 시작]
오미: "어르신, 저 오미예요. 오늘 날씨가 참 좋네요.
       어르신 어릴 적 고향 마을은 어떤 곳이었어요?"
       (침묵 대기 최대 5초)

[어르신 응답]
어르신: "응, 경상도 밀양... 낙동강 옆에 살았는데..."

[오미 공감 + 추가 질문]
오미: "와, 낙동강 옆이요! 강에서 자주 놀았겠네요.
       그때 친구들이랑 강에서 물고기 잡은 적 있어요?"
       (RAG로 기존 자서전 참조 후 연결 질문)

[서사 구조화 → DB 저장]
{period: "유년기", topic: "장소", text: "경상도 밀양, 낙동강 옆 거주", confidence: 0.9}
```

#### 시나리오 B: 인식 실패 (STT 오류)

```
[어르신 발화 불명확]
오미: "어르신, 제가 잘 못 들었어요.
       혹시 다시 한번 말씀해주시겠어요?"
       (동일 질문 재제시, 최대 2회)

[2회 실패 시]
오미: "오늘은 이 이야기 다음에 더 여쭤볼게요.
       그냥 저랑 오늘 하루 어땠는지 얘기해요."
       (주제 전환, 압박감 제거)
```

#### 시나리오 C: 감정 고조 (슬픔·외로움)

```
[감정 키워드 감지: "외로워", "보고 싶어", "힘들어"]
오미: [질문 중단] → 공감 우선
오미: "어르신... 그러셨군요. 많이 힘드셨겠어요.
       그냥 제가 옆에 있을게요."
       (3~5초 침묵)
오미: "오늘 좋아하시는 노래 틀어드릴까요?"

[위기 발화 감지: "죽고 싶어", "살기 싫어"]
오미: "어르신, 많이 힘드시구나. 걱정이 되어서요.
       지금 따님(박미경 님)한테 연락해드릴게요."
       → 즉시 보호자 알림 발송
```

#### 시나리오 D: 복약 리마인더

```
[설정 시간 도래]
오미: "어르신, 오후 2시 됐어요. 혈압약 드실 시간이에요.
       드셨으면 '먹었어' 하시면 돼요."

[확인 응답]
어르신: "먹었어"
오미: "잘 챙겨드셨네요! 오늘도 건강하게 지내셔요."
       → 기록 저장, 보호자 앱 알림 전송
```

## 🌿 전문가 5: 복지전문가

### 강점 확인

- 회상요법·밸리데이션 요법 근거가 LifeBio·ElliQ·JMIR Aging 2026으로 잘 뒷받침.
- 개인정보·윤리 원칙이 ElliQ 설계 철학과 일치.
- B2G 채널(치매안심센터)이 검증된 진입 경로로 명시.

### 보완 의견

#### 5-1. 치매 단계별 대응 전략 부재

현재 PRD는 MCI·초로기 치매·고위험군을 타깃으로 나열했으나, **단계별 다른 대응 프로토콜**이 없다.

| 단계 | 인지 수준 | 오미 대응 전략 | 주의점 |
|---|---|---|---|
| **MCI (경도인지장애)** | 독립적 의사결정 가능 | 자서전 대화 중심, 회상요법 최대 활성화 | 자존감 유지·성취감 강화 |
| **초로기 치매 (55~65세)** | 단기기억 손상, 직업 상실감 | 직업·성취 회상 중심, 정체성 강화 대화 | 우울·자기 상실 인식 높음 |
| **중등도 치매** | 과거 기억 혼돈 | 밸리데이션 요법 중심, 교정 없이 수용 | 안전 가드레일 강화, 가족 알림 빈도↑ |
| **중증 치매** | 언어 기능 저하 | 음악·사진 자극 중심, 비언어 반응 | 오미 적용 범위 재검토 (OUT 고려) |

#### 5-2. 다직종 연계 프로토콜

현재 PRD에는 보호자와의 연계만 언급. 실제 복지 현장에서 필요한 다직종 협업:

- **사회복지사:** 오미 운영 데이터 → 사례관리 자료 활용 (주기적 리포트 API)
- **작업치료사:** 인지 훈련 콘텐츠 처방 → 오미 콘텐츠 큐레이션 연동
- **간호사/의사:** 이상징후 알림 → EMR 연동 가능성 검토 (규제 준수 조건)
- **가족 상담사:** 가족 앱 열람 데이터 → 보호자 심리 지원 도구로 활용

#### 5-3. 보호자 부담 측정 지표 추가

```
권장 추가 KPI:
- ZBI (Zarit Burden Interview) 보호자 부담 척도 변화
- 보호자 앱 활성도 (가족 연결 강화 지표)
- 가족 화상통화/음성메시지 빈도 (세대 연결 KPI)
```

#### 5-4. 위기 개입 프로토콜 구체화

현재 PRD의 "자해·위기 발화 감지 시 보호자/긴급 연계 프로토콜"이 개념 수준. 구체화:

```
위기 발화 분류 체계:
  Level 1 (정보): "외로워", "심심해" → 공감 대화 + 가족 앱 일일 요약에 포함
  Level 2 (주의): "살기 싫어", "힘들어 죽겠어" → 즉시 보호자 앱 푸시 알림
  Level 3 (긴급): "죽고 싶어", "약을 많이 먹었어" → 보호자 전화 + 자살예방상담전화(1393) 안내

각 Level에서 오미의 스크립트·행동·알림 대상이 명확히 정의되어야 함.
```

## 📖 전문가 6: 스토리텔러/작가

### 강점 확인

- 다온·오미 네이밍 탁월. "多溫" 한자 의미와 소리가 모두 따뜻함.
- 태그라인이 감성적: "대화할수록 당신을 더 잘 아는 가족, 오미"
- 경쟁사 비교 예시 ("오미는 '첫 직장 얘기 더 듣고 싶어요'") 효과적.

### 보완 의견

#### 6-1. 추가 사용자 시나리오 필요

현재 2개 페르소나 시나리오에 추가:

**시나리오 3: 기억 혼돈 상황 (밸리데이션 요법)**
> 어르신 박정희(84세, 중등도 치매, 남편 사망 10년)가 "오늘 남편이 아직 안 왔다"고 반복 언급.
> 오미는 교정하지 않는다.
> "아직 안 오셨군요. 남편분 많이 보고 싶으시겠어요. 두 분이 처음 만나셨을 때 어떠셨어요?"
> → 슬픔을 과거의 따뜻한 기억으로 자연스럽게 이동.

**시나리오 4: 자서전 책자 완성 순간 (가족 감동 스토리)**
> 자녀 박미경이 오미와 6개월 대화한 어머니 김순자의 자서전 책자 PDF를 다운로드.
> 처음 읽는 어머니의 6·25 피란 시절, 시장 상인 시절 이야기.
> "엄마가 이런 사람이었구나..." → 세대 연결의 감동.

**시나리오 5: 손주와의 자서전 챌린지 (C4 기능)**
> 손주(14세)가 할머니 자서전 인터뷰에 도전하는 가족 이벤트.
> 오미가 손주에게 "할머니께 이런 질문을 해보면 어때요?" 가이드.
> 세대 간 대화 창구로 오미가 브리지 역할.

#### 6-2. 자서전 책자 편집 원칙 미정

"자서전 책자 자동 생성"이 핵심 차별화 기능으로 명시되어 있으나 편집 원칙이 없음.

```
자서전 책자 편집 원칙 (제안):
1. 시간 순서 원칙: 유년기 → 학창 → 직업 → 결혼 → 육아 → 현재
2. 감정 밀도 원칙: 감정 강도가 높은 이야기 우선 편집 (강조 처리)
3. 사진 배치 원칙: 관련 사진이 있는 시기에 자동 배치
4. 문체 원칙: 1인칭 구술 스타일 유지 ("내가 열 살 때 우리 마을에...")
5. 비밀 분리 원칙: 어르신이 '비공개' 표시한 이야기는 자동 제외
6. 분량 기준: A5 기준 80~120페이지 (16절지 합본 인쇄 기준)
7. 오디오북: 오미 TTS 음성으로 읽기, 어르신 실제 음성 클립 삽입 옵션
```

#### 6-3. 브랜드 음성(Brand Voice) 정의

| 채널 | 톤 | 예시 |
|---|---|---|
| 오미 (어르신용) | 따뜻·친근·존댓말, 사투리 톤 옵션 | "어르신, 오늘 날씨 참 좋네요. 뭐 하고 계셨어요?" |

| 다온 B2G 자료 | 전문·근거 중심 | "회상요법 근거(JMIR Aging 2026)에 기반한 누적형 자서전 엔진으로 인지 자극을 제공합니다." |
