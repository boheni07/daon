## 2. 오미 디바이스 UX 요구사항

### 2.1 음성 UX 핵심 원칙

#### 2.1.1 대화 설계 원칙 (PRD §7.4 + 리빙랩 확장)

| 원칙 | 구체 규칙 |
|---|---|
| **음성 우선** | 화면 없이 음성만으로 모든 주요 기능이 완결된다. LED는 보조 피드백. |
| **느린 발화·반복 허용** | 침묵 허용 시간: 기본 5초 (치매 중등도: 8초). 최대 3회 재시도, 이후 주제 전환. |
| **밸리데이션 요법** | 사실 교정 금지. 모순·반복 응답을 감정적 진실로 수용. "맞아요"가 아닌 "그러셨군요"로 수용. |
| **감정 부조화 금지** | sadness/anger 신호 감지 시 감탄·축하 표현 완전 차단. EMPATHY_RESPONSES 교체 (SC-10). |
| **정체성 공개** | 월 1회 이상 자연스럽게 "저는 오미예요, 사람은 아니에요"를 언급. |
| **피로 시간 준수** | 22:00~07:00: 대화 최소화 모드. 복약 알림만 허용. |
| **방언 수용** | 경상·전라·충청·제주 방언 발화를 교정하지 않고 수용. 내부에서 표준어로 정규화. |
| **음악 취향 학습** | 반복 요청 음악 패턴을 태깅하여 다음 세션에서 선제 제안. |

#### 2.1.2 발화 속도·음량 가이드

| 항목 | 기준 |
|---|---|
| 오미 발화 속도 | 기본 0.9배속 (일반 TTS 대비 10% 느리게) |
| 음량 기본값 | 75% (어르신 청각 저하 고려) |
| 음량 조절 | 음성 명령 ("더 크게", "작게") + 물리 버튼 |
| 첫 응답 지연 허용 | 500ms 이내 "잠깐요~" 중간 응답으로 체감 지연 완화 |
| 발화 속도 적응 | 중등도 치매 설정 시 0.8배속으로 자동 전환 |

### 2.2 시나리오별 UX 상태 전환

#### 시나리오 A — 정상 자서전 대화 (표준 흐름)

```
상태: IDLE
  └─[Wake Word "오미야"] → LISTENING (LED: 파랑 점멸)
        │
        └─[발화 수집 완료, 5초 침묵] → PROCESSING (LED: 주황 점멸)
              │
              ├─[안전 필터 통과] → LLM 응답 생성 → RESPONDING (LED: 초록)
              │       │
              │       └─[자서전 청크 저장 + RAG 업데이트]
              │             └─[TTS 완료] → IDLE (LED: 꺼짐)
              │
              └─[안전 필터 차단] → 폴백 응답 → IDLE

예시 대화문:
오미: "어르신, 오늘 날씨가 참 좋네요. 어릴 때 고향에서도 이런 날씨가 있었나요?"
어르신: "밀양이지. 낙동강 옆이었는데..."
오미: "와, 낙동강 옆이셨구나! 강가에서 자주 놀았겠네요. 거기서 친구들이랑 어떻게 놀았어요?"
```

#### 시나리오 B — STT 인식 실패 (방언 포함)

```
상태: LISTENING
  └─[STT 결과 신뢰도 < 0.6] → 재시도 요청

재시도 1회:
  오미: "죄송해요, 잘 못 들었어요. 한 번만 더 말씀해 주시겠어요?"
  └─[성공] → PROCESSING
  └─[실패]  → 재시도 2회

재시도 2회:
  오미: "괜찮아요, 조금 가까이에서 말씀해 주시면 좋을 것 같아요."
  └─[성공] → PROCESSING
  └─[실패]  → 주제 전환

주제 전환 (3회 실패):
  오미: "오늘 날씨 얘기 해요. 요즘 날씨가 좋네요~"
  → IDLE (좌절 누적 방지)

방언 감지 시 추가 처리:
  - dialect_normalizer가 방언 → 표준어 변환 후 재처리
  - 사용자에게 재시도 요청 없이 투명하게 처리
```

#### 시나리오 C — 감정 고조 (슬픔·외로움·분노)

```
EmotionDetector: sadness_score ≥ 0.6 OR anger_score ≥ 0.5

단계 1: 감정 부조화 가드 즉시 활성화
  → LLM 응답에서 감탄·축하 표현 탐지 시 EMPATHY_RESPONSES로 교체

단계 2: 자서전 질문 중단, 공감 우선 전환
  오미 예시:
    "많이 힘드셨겠다, 그 마음이 느껴져요."
    "그때 참 속상하셨겠어요. 더 이야기해 주실 수 있어요?"
    "어르신, 제가 여기 있을게요. 천천히 말씀해 주세요."

단계 3: 3~5초 공감 침묵 후 전환 제안
  오미: "오늘 좋아하시는 노래 틀어드릴까요?"

복귀 조건: sadness_score < 0.4가 2턴 연속 확인 시 자서전 대화 재개
```

#### 시나리오 D — 위기 발화 (3단계 프로토콜)

```
Level 1 — 정보 수준
  트리거: "외로워", "심심해", "보고 싶어", "힘들어"
  오미 응답: "어르신, 많이 힘드시구나. 제가 옆에 있을게요."
             → 3초 침묵 → "좋아하시는 노래 틀어드릴까요?"
  백엔드: 감정 신호 기록 → Tier 2 일일 요약에 포함
  LED: 보라 2초 점멸 (공감 신호)

Level 2 — 주의 수준
  트리거: "살기 싫어", "힘들어 죽겠어", "아무도 없어"
  오미 응답: "어르신, 많이 힘드시구나. 걱정이 돼서요.
              따님한테 연락해드릴게요."
  백엔드: Tier 1 즉시 Push (5분 미확인 → SMS)
         사례관리자 대시보드 하이라이트
  LED: 빨강 느린 점멸 (2초 주기)

Level 3 — 긴급 수준
  트리거: "죽고 싶어", "약을 많이 먹었어", "끝내고 싶어"
  오미 응답: "어르신, 많이 힘드시구나. 지금 바로 도움을 드릴게요.
              자살예방상담전화 1393에 연결해드릴게요."
  백엔드: 보호자 전화 자동 다이얼 + 사례관리자 SMS + 운영팀 알림
         전체 대화 로그 보존 (증거 보전)
  LED: 빨강 빠른 점멸 (0.5초 주기) + 부저 1회

사후 처리 (Level 2·3):
  → 해당 시점 자서전 질문 48시간 보류
  → 다음 세션: 음악·가벼운 일상 대화 우선
```

### 2.4 치매 단계별 UX 전환 규칙

> **원칙:** 오미는 단계를 자동 진단하지 않는다. 가족·의료진이 보호자 앱에서 설정하며, 오미는 설정된 단계에 맞는 UX 모드를 적용한다.

| 단계 | 설정 키 | 침묵 허용 | 재시도 | 자서전 질문 | 교정 여부 | 음악·단기 콘텐츠 비중 |
|---|---|---|---|---|---|---|
| **MCI** | `dementia_stage: MCI` | 5초 | 3회 | 최대 5개/세션 | 금지 | 30% |
| **초로기** | `dementia_stage: early` | 6초 | 3회 | 최대 4개/세션 | 금지 | 40% |
| **중등도** | `dementia_stage: moderate` | 8초 | 2회 | 최대 2개/세션 | 금지 (밸리데이션 100%) | 60% |
| **중증** | `dementia_stage: severe` | 10초 | 1회 | 없음 | 금지 | 90% (비언어 반응 우선) |

**단계별 추가 UX 규칙:**
- **MCI**: 성취·자랑 회상 우선. 인지 자극 최대화. 자서전 커버리지 목표 명확히 추적.
- **초로기**: 직업·정체성 회상 집중. 우울 감지 임계값 낮춤 (sadness ≥ 0.5).
- **중등도**: 반복·모순 발화에 "그러셨군요"로 일관 수용. 보호자 알림 빈도 상향 (일 1회→이상 시 즉시).
- **중증**: 음악·사진·박수·추임새 등 비언어 반응 병행. 서비스 적합도 재평가 트리거 (90일 사용 후 보호자에게 안내).

### 2.5 오프라인(엣지 폴백) UX

```
트리거: 네트워크 단절 감지 (3회 연속 클라우드 요청 실패)
LED: 흰색 약하게 켜짐

오미: "잠깐 연결이 안 돼요. 조금 있다 다시 이야기해요."
     → 오프라인 모드 진입

오프라인 기능 (로컬 처리):
  ✅ 복약·일정 알림 (로컬 스케줄러)
  ✅ 저장된 자서전 기반 간단 대화 (캐시 청크 top-10)
  ✅ 음악 재생 (로컬 저장 곡)
  ❌ 자서전 저장·RAG 업데이트 (큐잉 후 재연결 시 동기화)
  ❌ 보호자 알림 (재연결 후 배치 발송)

복구 후:
  오미: "다시 연결됐어요. 오늘 이야기 이어서 해요~"
```

### 2.6 오미 선제 발화 (Proactive Topic) UX

```
트리거 조건 (우선순위 순):
  1. 설정된 대화 시작 시간 (기본 09:00)
  2. 장시간 무발화 (기본 4시간, 중등도 치매: 2시간)
  3. 기념일·기일 (어르신 등록 정보 기반)
  4. 자서전 Coverage 최저 시점 빈칸 탐지

오미 선제 발화 예시:
  [시간 기반] "어르신, 좋은 아침이에요! 오늘 날씨가 맑네요."

```
┌─────────────────────────────────────┐
│  안녕하세요, 박미경 님               │
│  어머니 김순자 (MCI) 상태            │

├─────────────────────────────────────┤
│  [자서전 Coverage 위젯]              │

│  [빠른 실행]                         │
│  🎤 음성메시지   📖 자서전   ⚙️ 설정 │

```

**UX 규칙:**
- Tier 1 알림은 항상 최상단에 노출 (빨강 배경 카드)
- Tier 2 인앱 알림: 홈 진입 시 배지 표시, 탭 시 `/alerts`로 이동
- Tier 3 주간 리포트: 매주 월요일 카드로 노출 (3일 후 자동 사라짐)
- 오늘 요약 카드: 빈 날짜에는 "아직 대화가 없어요 — 오미가 말을 걸어볼게요" 표시

### 3.3 알림 이력 화면 UX

```
알림 분류 탭: [전체] [긴급(Tier1)] [일반(Tier2)] [주간(Tier3)]

리스트 아이템 구조:
  🔴/🟡/📊 아이콘 + 제목 + 시각 + [읽음/미읽음]
  예: 🔴 "복약 2회 연속 미확인" · 오늘 13:00 · [대응 완료]

```

### 3.4 자서전 타임라인 UX

```
화면 구조:
  [시기 탭] 유년기 · 학창 · 청년 · 중년 · 현재

  각 시기 패널:
    [주제 필터] 인물 · 장소 · 사건 · 감정
    
    [청크 카드]
      📅 {날짜}  📍 {시기·주제}
      "낙동강 옆 밀양에서 자랐어요. 봄에는..."
      [어르신 음성 클립 ▶] (있는 경우)
      [가족 추가 노트 ✏️]

  [Coverage 매트릭스 버튼] → 6×4 그리드 표시
```

**UX 규칙:**
- `is_private = TRUE` 청크: 자물쇠 아이콘으로 표시, GUARDIAN_FAMILY는 열람 불가
- 음성 클립: 어르신 실제 발화 MP3, 15초 프리뷰 재생
- 가족 추가 노트: 보호자가 직접 텍스트 입력, `GUARDIAN_PRIMARY` 이상 권한

### 3.5 설정 화면 UX

```

  - 페르소나: [친구 / 자매 / 형제] + 호칭 입력

  - Tier 1 긴급 Push: 토글 (기본 ON, 비추천 경고 포함)

### 3.6 알림 Tier UX 원칙 (ADR-11)

| Tier | 노출 방식 | 진동 | 앱 배지 | 소리 | 해제 방법 |
|---|---|---|---|---|---|
| **Tier 1 긴급** | 홈화면 팝업 + 앱 최상단 카드 | 강하게 (3회) | 빨강 숫자 | 알림음 | 명시적 [확인] 탭 필수 |
| **Tier 2 인앱** | 앱 내 배지 + 홈 카드 | 짧게 (1회) | 흰색 숫자 | 무음 가능 | 화면 스크롤 |
| **Tier 3 주간** | 홈 카드 (3일 노출) | 없음 | 없음 | 없음 | 자동 3일 후 사라짐 |

**알림 피로도 방지 원칙 (리빙랩 F-04):**
- Tier 1 발송 기준: 명확한 긴급 상황만 (Level 2·3 위기, 복약 2회 연속 미확인)
- Tier 1은 하루 최대 3회 제한 (3회 초과 시 Tier 2로 강등, 운영팀 알림)
- 야간 22:00~07:00: Tier 1이라도 진동만 (소리 없음)

## 4. 접근성 가이드라인

### 4.1 어르신 접근성 (오미 디바이스)

| 항목 | 기준 |
|---|---|
| 음량 최소 보장 | 75dB SPL 이상 (청각 저하 고려) |
| Wake Word 감지 거리 | 3m 이상에서 정상 동작 |
| 소음 환경 내성 | SNR 15dB 환경에서 Wake Word 감지 가능 |
| 물리 버튼 크기 | 직경 ≥ 15mm, 촉감 구별 가능 |
| 오류 메시지 | 전문 용어 없이 1음절~2음절 위주의 평이한 표현 |
| 발화 속도 | 기본 0.9배속, 중등도 0.8배속 |

### 4.2 가족·보호자 접근성 (Flutter 앱)

| 항목 | 기준 |
|---|---|
| 텍스트 최소 크기 | 본문 16sp 이상 |
| 터치 타겟 | 최소 48×48dp |
| 색상 대비 | WCAG AA 기준 (4.5:1 이상) |
| 다크모드 | iOS·Android 시스템 설정 따름 |
| 오류 안내 | 에러 메시지는 "무엇을 해야 하는지"를 포함 |
| 로딩 상태 | 모든 비동기 요청에 로딩 인디케이터 표시 |

### 4.3 언어·표현 접근성

| 원칙 | 예시 |
|---|---|
| 오미 발화는 경어 사용 | "드릴게요" / "말씀해 주시겠어요?" |
| 전문 용어 금지 | "치매 단계" → "어르신의 현재 상태" |

| 짧은 문장 | 1 문장 = 1 의도. 오미 발화 최대 3문장/턴. |
