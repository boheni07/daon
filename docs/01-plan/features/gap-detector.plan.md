## 4. 검증 절차

### Phase 1 — 수치·임계값 교차 검증

각 문서에서 `grep` 기준 키워드로 값 추출 후 대조:

```
검색어 목록:
- "0.6" or "sadness" → V-01
- "85%" → V-02
- "90일" or "TTL" → V-03
- "1.5초" → V-04
- "80%" → V-05
- "99.9%" → V-06
- "0%" + "감정 부조화" → V-07
```

### Phase 2 — 열거형 교차 검증

```
검색어 목록:
- "경상·전라·충청·제주" or "방언" → E-01
- "PERIODS" or "자서전" + "시기" → E-02
- "Tier 1" or "Tier 2" or "Tier 3" → E-03
- "MCI" or "초로기" or "중등도" or "중증" → E-04
- "Level 1" or "Level 2" or "Level 3" → E-05
```

### Phase 3 — API 계약 대조

D2 §2.3.1 API 목록 vs D3 §4.2 API 계약 표를 1:1 매핑:
- endpoint URL
- HTTP method
- request/response 필드

### Phase 4 — 성공 기준 커버리지

SC-09~SC-12가 D1(PRD)~D4(워크플로우)에 모두 반영되어 있는지 확인:

| SC | D1 | D2 | D3 | D4 | D5 |
|---|:--:|:--:|:--:|:--:|:--:|
| SC-09 방언 ≥85% | ✓ | ✓ | ✓ | ✓ | ✓ |
| SC-10 감정부조화 0% | ✓ | ✓ | ✓ | ✓ | ✓ |
| SC-11 알림만족도 ≥80% | ✓ | ✓ | ✓ | ✓ | ✓ |
| SC-12 유산패키지 ≥99.9% | ✓ | ✓ | ✓ | ✓ | ✓ |
